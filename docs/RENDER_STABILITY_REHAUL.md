# Render stability first

- PS1/Dreamcast: floor merging is restricted to valid cells and cannot hide an exposed quadrant. Camera-adjacent buildings have one geometry owner. Local ground is emitted before optional detail and clips at the near plane. Nonrectangular roof regions cannot use the single bounding slab. No changes to saved data are required.
- DS/DSi: cache pieces are rebuilt for the same lot/geometry snapshot, rather than assembling new walls with old furniture or surrounding streets. Discard queued geometry before lot/mode/options transitions. Each static list establishes its own GPU state. A segment overflow must not submit a malformed chain. Never overwrite a referenced character model.
- Dreamcast: protect PowerVR texture pages referenced by the CPU-side submission from eviction or in-place modification, including changes during packet traversal. Texture pressure is counted rather than silently substituting unrelated textures. Opaque primitives are not blocked by a full translucent list.
- Android: pool, paths, farm and skate surfaces belong to a single terrain mesh; fountain rims are disjoint. Prefer 24-bit depth with old-device fallback. This addresses depth fighting without deleting visible terrain.

These are source-level corrections, not a claim of flicker-free play. Verify long moving-camera, lot-crossing, texture-pressure and dense-neighborhood runs on every platform before release. Save compatibility is no longer a design constraint for future changes, but intentionally deleting existing save files is unnecessary.

## Temporal regression coverage

The moving-house test now captures 53 native 320x240 images, including two 25-vblank bursts. A conservative A/B/A comparison at multiple time offsets flags large, brief flashes even when widely spaced screenshots appear normal. Ordinary gradual camera motion and constant images are exercised by synthetic detector self-tests. This is a PS1 emulator smoke test, not evidence that every kind of flicker has been eliminated; read the saved results and inspect the burst captures.

## Coherent streaming and submission follow-up

The pending-lot queue now survives repeated rebases; unfinished lots are not saved or traversable and only one ordinary generation job is serviced per update. All newly generated roof metadata publishes before drawing, while independently drawn local proxies cover unfinished buildings even with distant scenery disabled. Partial buildings crossing the window boundary force a metadata rebuild instead of retaining dangling IDs. Cutaway transitions use a hysteresis band and terrain-correct height, and full-wall mode no longer opens unrelated buildings. Gameplay milestone flashes have become text notifications. DS restores the dynamic recorder's state after temporary model recording and uses a low-cost model if a cache slot is too small. Android commits a scene's CPU and GPU geometry together; failed replacement uploads retain the previous buffer and the map remains available. No FPS or flicker-free claim until visual validation.

## Capacity and boundary follow-up

The four-by-four block city is 72 tiles per side inside the 80-tile allocation. Streamed map/roof/dirty-mask shifts now respect that boundary, and padding is not walkable or editable. Local skyline faces and clipped triangles use the same GTE depth scale as detailed geometry, instead of sorting a whole building into a distant slot. The console city draws structure and roofs before furniture; nearby props are considered first, with a bounded lower-detail model path and counters when room is exhausted. DS reserves more geometry for surrounding lots and submits adjacent building shells ahead of optional landscaping. These policies trade optional detail for continuity under pressure; final visual results require actual native tests.

## Unified depth and clipped-geometry follow-up

All skyline faces, clipped triangles and tree cards now use a shared quarter-depth ordering scale with reserved floor/shadow indices. Software clipping uses the same terrain-lifted matrix translation as GTE rendering; merged roof faces retain their actual 2x2 or 4x4 extent when clipped. A coarse ground layer remains underneath the detail region, and the scratchpad records exact per-frame local tree ownership to avoid drawing both a model and its card. Town tree masks are evaluated only near the requested tree radius or when a cell becomes visible; terrain caching no longer requires four extra lot queries for every town cell. Android tags meshes and pick events by the request revision and publishes the selected neighborhood only after a successful GPU upload. This prevents same-coordinate stale picks across new worlds. Native verification remains necessary; these changes do not guarantee 30 FPS.

## Default-timing streaming regression

A separate native emulator job builds with AUTO_CITY only, on the stock 2 MiB model, and runs 7,200 vblanks. It reports live frame delivery (rather than forced A/B timing), world-window crossing count, worst rebase cost and packet allocation failures. Two short consecutive-vblank capture bursts screen for large isolated flashes. The test requires at least two actual window shifts; it does not pretend that scripted movement tests physical collision or that a report guarantees 30 FPS. The results are uploaded as JSON and screenshots.

## Regression recovery

The first stock-timing replay failed in the native emulator with repeated exceptions at 80000080. This is consistent with the project's previous resident RAM/stack failures, but the exact root cause is not proven. Restore about 5.5 KiB in resident data (explicit opt-in full sampling histogram, byte-packed skyline cell coordinates, local town offsets), plus smaller far-renderer code, retaining all building and packet capacities. An ELF _end guard reports and requires 8 KiB static stack headroom for the traversal replay; log diagnostics are retained on failure. Android portrait/orbit passed but landscape readiness failed. The layout now keeps one attached GL surface across rotation, changes weights instead of rebuilding the Activity, provides scrollable controls in both orientations, and dispatches renderer callbacks directly on the main looper. Native test also rotates back to portrait. None of this is marked verified until the replacement runs finish.

## Stock-speed follow-up after the verified crash recovery

The eef857ef native traversal completed 1,100 live frames at 11.82 FPS with three world shifts, zero packet allocation failures and no isolated flashes in the sampled bursts. To reduce actual cost rather than remove objects wholesale, distant local tree models now use one terrain-anchored card while keeping near-camera trees in geometry (PS1); the local vegetation remains independently of the speed helper's far-view setting. The far camera setup is cached within the frame. A coarse ground tile wholly behind the near plane is discarded before software clipping. Roof regions revalidate only affected buildings, with a full metadata rebuild if a retained custom house intersects the generated block across its boundary. The close-prop pass visits only its bounded square, and its distant pass skips that square. Traversal JSON now reports per-phase hblank costs, primitive counts, helper pressure and detail radius, so further tuning can follow measured costs. FPS gains must be measured, not presumed.

## Persistent city exterior and terrain reconstruction

Manual review of native frame captures revealed huge material-blind color patches where the previous 8x8 ground proxy sampled just its central tile. The default helper had collapsed the detailed radius to roughly five tiles, exposing this fallback. Replace it with disjoint cached material rectangles aligned to the actual 18-tile block; retain real road and pavement widths, including the planned street while a lot is being generated. Full checkerboard/custom layouts use a complete temporary rectangle list rather than truncate. Clip far polygons to a real viewport margin, not a 3x guard band that exceeded PS1 primitive size limits. A building now has one whole-building owner, independent of the adaptive floor detail radius, with a deadband. Validate L-shaped proxy footprints and upstairs perimeter against real tiles; other irregular footprints stay exact when visible. Closed houses omit hidden internal walls but retain exterior doors. AUTO cutaway reveals the occupied building with a short exit hold; explicit CUT AWAY retains ray-based reveal, FULL WALLS keeps roofs. Maintain a bounded 90m skirt when distance detail is zero, no automatic haze toggling, and preserve road width across the loaded window. Expand traversal captures from two to nine temporal bursts. These are source changes; native visual and FPS revalidation is still required.
